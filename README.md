# AI 项目需求管家 · 使用说明与开发进度

## 这是什么

一款中文网页工具，帮助接网站、小程序项目的小工作室和独立开发者，把零散的客户沟通整理成**有原文证据的需求草稿**，经人工确认形成**不可修改的版本**，再把后续沟通与版本比较，生成**可逐条审核的变更清单**。

本仓库当前处于 **M4（试用准备）** 阶段：已完成登录认证、项目级访问控制、输入上限与请求限额、数据备份恢复，并给出部署说明。数据用 SQLite 持久化，支持历史版本、Markdown 导出与真实模型分析。

## 如何启动

需要 Python 3.10+，并已安装依赖：

```bash
pip install fastapi "uvicorn[standard]" pydantic
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

启动后在浏览器打开：

> **http://127.0.0.1:8000/**

数据保存在项目根目录的 `app.db`（SQLite）。关闭命令行停止服务；再次启动后数据仍然存在。

**首次使用需先注册一个账号**（打开页面会自动进入登录/注册页）。每个用户只能看到自己的项目；项目所有者可邀请其他用户协作。

## 如何配置模型 API 密钥（重要）

模型密钥**只放在后端环境/.env 文件中**，绝不进入前端代码、导出文件或源码仓库。配置步骤：

1. 把项目根目录的 `.env.example` 复制为 `.env`（`.env` 已在 `.gitignore` 中，不会被提交）。
2. 在 `.env` 里填写三项必填值：

```ini
LLM_API_KEY=你的密钥
LLM_BASE_URL=接口基础地址
LLM_MODEL=模型名
```

支持任意提供「OpenAI 兼容」`/chat/completions` 端点的服务商，例如：

| 服务商 | LLM_BASE_URL | LLM_MODEL（示例） |
| --- | --- | --- |
| DeepSeek | https://api.deepseek.com/v1 | deepseek-chat |
| Moonshot(Kimi) | https://api.moonshot.cn/v1 | moonshot-v1-8k |
| 智谱 GLM | https://open.bigmodel.cn/api/paas/v4 | glm-4-flash |
| 通义千问 | https://dashscope.aliyuncs.com/compatible-mode/v1 | qwen-plus |
| OpenAI | https://api.openai.com/v1 | gpt-4o-mini |

3. 重启服务（`Ctrl+C` 后重新运行上面的启动命令），顶部状态栏会显示「模型已配置：xxx」。

不配置密钥也能运行：任务书第 8 节的固定示例材料走内置结果并标注「示例模式」；其他输入会明确提示「尚未配置模型」，不会伪造分析结果。

## 如何验证核心流程

1. 打开首页，点「**＋ 新建项目**」，输入任意项目名。
2. 点工作台「**载入示例材料**」，再点「**保存材料**」——此时保存的是任务书第 8 节的固定示例 SRC-001。
3. 点「**整理需求**」→ 需求清单出现 8 条候选（首页/产品列表/产品详情/联系我们 = 提出；在线支付/会员 = 排除；后台维护方式 = 待澄清）。界面顶部有橙色「**示例模式**」横幅。
4. 可以在草稿里改文字、删条目，然后点「**确认并保存版本**」→ 生成 **V1**（每条需求获得稳定 ID，如 REQ-0001）。
5. 回到「原始沟通」，手动粘贴任务书第 8 节的 SRC-002 内容，保存后点「**分析新沟通**」→ 变更对比区出现 3 条候选（会员登录 = added 并与 V1 排除项冲突、专属价格 = clarification 待澄清、在线支付 = unchanged 仍排除）。
6. 在每条变更上点「**采纳**」或「**忽略**」，再点「**根据采纳项生成新版本**」→ 生成 **V2**（V1 快照保持不变，V2 保留父版本关系）。
7. 顶部「**导出 Markdown**」可下载完整需求文档（含需求清单、历史版本、变更记录）。
8. 工作台底部「**历史版本**」区可查看/导出任意历史版本。

## 已实现

### M1（页面流程）
- 项目创建与列表、粘贴文本、保存材料、按 ID 查看原文。
- 整理需求草稿（候选 / 排除项 / 待澄清），每条带 source_id 与原文引用。
- 草稿可编辑删除；人工确认生成不可修改版本；对照基线分析新沟通并逐条采纳/忽略。
- 中文界面，三/四个区域，手机上纵向排列。

### M2（数据与版本）
- **SQLite 持久化**：Project / Source / Draft / Version / AnalysisRun / ChangeDecision 六张表，重启后数据保留（T15）。
- **不可变版本**：确认后快照永久保存，V2 生成后 V1 内容与稳定 ID 均不变（T11）。
- **事务 + 幂等**：确认/生成版本在事务内完成；同一 request_id 重复提交只创建一个版本（T12）。
- **稳定需求 ID**：正式需求由后端分配 REQ-xxxx，不信任模型自报的确认状态（规则 8）。
- **过期分析拦截**：采纳时检查分析所用基线仍是当前版本，否则返回 409 要求重新比较（T13）。
- **历史版本查看 + Markdown 导出**。

### M3（真实模型）
- **模型接入**：`backend/llm.py` 通过 OpenAI 兼容接口调用任意服务商，密钥只读后端环境/.env。
- **版本化提示词**：`backend/prompts.py` 实现任务书第 7 节的两份提示词，`PROMPT_VERSION` 记录到分析记录。
- **结构化校验**：`backend/validators.py` 校验候选类型、意图、字段约束，以及证据 source_id 归属与原文逐字存在、关联 requirement_id 归属（T08）。
- **失败处理**：未配置/超时/HTTP 错误/无效响应分别给出中文提示，最多自动重试一次，原始输入始终保留（T09/T10）。
- **用量记录**：模型标识、提示词版本、token 用量、耗时写入 AnalysisRun。

### M4（试用准备）
- **身份认证**：注册/登录/登出，PBKDF2 密码哈希（`backend/auth.py`）+ 服务端会话令牌（7 天过期）。
- **项目级访问控制**：每个项目接口校验 owner / membership；他人用你的项目 ID 调用返回 404，不泄露存在性（T16）。
- **成员协作**：项目所有者可邀请其他用户（`/members`），成员只读可写、不可再邀请。
- **输入上限**：单条材料上限（默认 50000 字符）、单次分析总长度上限（默认 200000 字符），超限明确提示分批处理，不悄悄截断。
- **请求限额**：分析类接口按用户限流（默认 60 秒 20 次），超出返回 429。
- **数据备份恢复**：`python backend/backup.py backup` / `restore`。
- **部署说明**：见 `DEPLOY.md`。

## 已知问题与边界

- **示例模式**：任务书第 8 节的**固定示例材料**仍走内置结果并标注「示例模式」；其余输入调用真实模型。未配置密钥时，新输入明确提示「尚未配置模型」，绝不伪造结果（规则 9）。
- 模型密钥只存后端环境/.env，不进入前端代码、导出文件或源码仓库。
- SQLite 为单文件本地库，多用户托管需换托管数据库 + 反向代理 HTTPS（见 DEPLOY.md）。
